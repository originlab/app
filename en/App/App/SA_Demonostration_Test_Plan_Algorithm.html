Plans allowing failures (m >= 1)

When *m* ≥ 1, the full binomial sum must be used:

$$ \sum_{k=0}^{m} \binom{n}{k} \, p(\theta_0)^k \, \big[1 - p(\theta_0)\big]^{n-k} = \alpha $$

This equation generally has no closed-form solution for *t* or *n*. The tool solves it numerically (for example, by bisection or Newton-type methods) after substituting the appropriate reliability function *R*(*t* | *θ*₀) for the selected distribution.

- If *n* is fixed, the unknown is *t*, which enters through *p*(*θ*₀) = 1 − *R*(*t* | *θ*₀). - If *t* is fixed, the unknown is *n*, which appears in the binomial coefficients and exponents. The solution is rounded up to the nearest integer.

---

    1. 5. Role of the Life Distribution

The algorithm is distribution-agnostic up to the definition of *R*(*t* | *θ*). The user’s choice of distribution provides the mapping between test time *t* and failure probability *p*(*θ*₀). For example:

- Exponential: *R*(*t* | *θ*) = exp(−*t* / *θ*) - Weibull: *R*(*t* | *η*) = exp[−(*t* / *η*)*β*] - Lognormal, normal, logistic, etc.: each has its own survival function.

Regardless of the distribution, the confidence-bound construction and the design equation remain the same.

---

    1. 6. Converting User Goals to a Common Parameter

The tool allows the reliability target to be entered in four different ways (scale/location, percentile, reliability at a time, or MTTF). Each of these is converted to a common target parameter *θ*₀ using the inverse relationships of the chosen distribution. Only then is the binomial design equation applied.

For instance:

- A **reliability-at-time** target *R* at time *t*0 is converted to the parameter value *θ*₀ that satisfies *R*(*t*0 | *θ*₀) = *R*. - A **percentile** target *t*p at cumulative failure probability *p* is converted to the parameter value *θ*₀ that satisfies *F*(*t*p | *θ*₀) = *p*, where *F* = 1 − *R*. - An **MTTF** target is converted to the corresponding scale or location parameter via the mean formula of the chosen distribution.

Once *θ*₀ is determined, the same exact-binomial design equation is solved.

---

    1. 7. Actual Confidence Level

When the tool computes a sample size, the result must be an integer. The theoretical *n* is therefore rounded upward. Because a larger sample size increases the chance of a pass at any fixed true reliability, the **actual confidence level** is slightly greater than the target 1 − *α*.

When the tool computes a test time *t* given an integer sample size *n*, no rounding is needed, and the actual confidence level equals the target exactly.

---

    1. 8. Probability of Passing Curve

The Probability of Passing (POP) curve plots the probability of a pass as a function of the true parameter value. For a true parameter *θ*:

$$ P_{\text{pass}}(\theta) = \sum_{k=0}^{m} \binom{n}{k} \, p(\theta)^k \, \big[1 - p(\theta)\big]^{n-k} $$

where *p*(*θ*) = 1 − *R*(*t* | *θ*).

By construction, at the target *θ* = *θ*₀, the pass probability equals *α* (typically 5%). As the true reliability improves (*θ* increases relative to *θ*₀), the pass probability rises. The POP curve therefore helps the user judge whether the chosen plan is practical: if even a substantially better-than-target product has only a modest chance of passing, the user may wish to increase *n*, increase *m*, or extend *t*.
